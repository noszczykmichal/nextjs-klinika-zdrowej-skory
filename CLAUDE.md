# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing website for "Klinika Zdrowej Skóry" (a cosmetology clinic in Warsaw). Next.js App Router + React 19 + TypeScript, content served from a headless Sanity CMS, deployed on Vercel. UI copy, route segments and SEO metadata are in **Polish**. The Sanity schema lives in a separate repo: [studio-klinika-zdrowej-skory](https://github.com/noszczykmichal/studio-klinika-zdrowej-skory).

## Commands

```bash
npm ci --legacy-peer-deps   # install (CI uses --legacy-peer-deps; plain install may fail on peer deps)
npm run dev                 # dev server with Turbopack (http://localhost:3000)
npm run build && npm start  # production build / serve
npm run lint                # ESLint (flat config, includes jsx-a11y + prettier)
npm test                    # Jest component tests (coverage is always collected)
npx jest path/to/Component.test.tsx      # single test file
npx jest -t "test name"                  # single test by name
npm run coverage:ci         # what CI runs for unit tests
npm run cypress:run-e2e     # Cypress e2e — requires the app running on :3000
```

CI ([.github/workflows/ci.yaml](.github/workflows/ci.yaml)) on push/PR to `main`/`dev`: lint → Jest → build + Cypress e2e (Chrome).

## Architecture

### Routing / content model
Three parallel resource sections share the same 3-level structure — index → category → item:
- `/zabiegi/[treatmentCategory]/[treatment]` — resource type `treatment`
- `/szkolenia/[trainingCategory]/[training]` — resource type `training`
- `/blog/[postCategory]/[post]` — resource type `post`

`ResourceType` (`"treatment" | "training" | "post"`, in [src/types/types.ts](src/types/types.ts)) drives everything. Sanity document types and fields are derived from it by naming convention: `${type}`, `${type}Category`, `${type}Slug`, `${type}Category->categorySlug`. When adding a new section, follow this convention so the generic queries keep working.

### Data fetching
- All Sanity GROQ queries live in [src/utils/sanityPageData.ts](src/utils/sanityPageData.ts), using the client from [src/sanity/client.ts](src/sanity/client.ts) with ISR `{ next: { revalidate: 30 } }`. Some fetchers are wrapped in React `cache()` so `generateMetadata` and the page component share one request.
- Pages are async server components: fetch via these helpers, call `notFound()` when they return `null`.
- Metadata is generated by factories in [src/utils/metadata.ts](src/utils/metadata.ts) (`createCategoryMetadataGenerator(type)`, `createResourceMetadataGenerator(type)`, …).
- Image blur placeholders are created server-side with `plaiceholder` ([src/utils/serverSideUtils.ts](src/utils/serverSideUtils.ts)); Sanity image URLs via `urlFor` in [src/utils/clientSideUtils.ts](src/utils/clientSideUtils.ts). `next.config.ts` only allows images from `cdn.sanity.io/images/ddh0mvo4/**`.
- Rich text uses Portable Text with custom renderers in [src/utils/portableTextComponentConfig.tsx](src/utils/portableTextComponentConfig.tsx) and [src/components/PortableText/](src/components/PortableText/).
- Static config (nav items, social links, form field definitions + validators) is in [src/utils/config.ts](src/utils/config.ts). Root layout fetches nav data from Sanity and renders `Navigation`/`Footer` around every page.

### Components
- `src/components/ui/*.tsx` — shadcn/ui generated components (config in `components.json`); excluded from coverage, `sidebar.tsx`/`carousel.tsx` excluded from lint. Prefer not to hand-edit.
- `src/components/ui/custom/` — project-specific reusable components (shared across the three resource sections).
- `src/components/<PageName>/` — page-specific components. Each component has its own folder `Name/Name.tsx` with a colocated `Name.test.tsx`.
- Global UI state (mobile side-nav open/closed) is in [src/store/uiContext.tsx](src/store/uiContext.tsx). In tests wrap components with `MockProvider` from [src/test-utils/mockContextProvider.tsx](src/test-utils/mockContextProvider.tsx); shared fixtures in `src/test-utils/mockData.ts`.
- Forms use React Final Form and POST to Formspree (contact form in the footer, course enrollment form).
- SVG imports become React components via SVGR (configured for both webpack and Turbopack in `next.config.ts`); use `*.svg?url` to get a URL under webpack.

### Analytics (Google Ads)
[src/lib/gtag.ts](src/lib/gtag.ts) + [src/components/analytics/](src/components/analytics/): gtag loading, Consent Mode v2 with a cookie-consent banner (choice stored under `cookie-consent`), and conversion tracking for phone clicks, form submits and Booksy links. Configured via env vars `NEXT_PUBLIC_GOOGLE_ADS_ID`, `NEXT_PUBLIC_ADS_LABEL_PHONE|FORM|BOOKSY`; tracking is a no-op when they're empty. `NEXT_PUBLIC_SITE_URL` sets `metadataBase`.

## Conventions
- Import alias `@/*` → `src/*`.
- Styling: Tailwind CSS v4 (`src/styles/globals.css`, CSS variables in `variables.css`); `cn()` from `src/lib/utils.ts` for class merging.
- Prettier: double quotes, semicolons, trailing commas, 80 cols, Tailwind class sorting plugin.
- Unused vars/args must be prefixed with `_` to pass lint.
